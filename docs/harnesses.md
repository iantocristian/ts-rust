# Experiment harnesses

A metric producer's evidence envelope proves which command ran against which
inputs; it cannot prove that the command measured the intended thing. This page
is the reviewable half: what each experiment harness actually asserts, over what
denominator, and what it deliberately leaves for a later sprint.

`status/runs.toml` registers the commands, [Tracking](TRACKING.md) defines the
evidence contract, and `status/experiments.toml` holds the typed criteria.

## e4: strings, positions and the leaf helpers

**Command.** `python3 scripts/e4-harness.py`.

**Shape.** A differential comparison against the pinned Corsa, not a set of
hand-written expectations. Two programs read the same checked-in fixture
manifest and each writes one JSON object per criterion of `probe -> value`
pairs:

| Side | Program | Answers come from |
|---|---|---|
| Oracle | `oracle/e4` | exported entry points of the pinned `internal/...` packages |
| Port | `crates/ts_e4_harness` | `ts_jsstring` |

Neither side sees the other's answers. A criterion passes only when the two
objects have exactly the same keys and every value is identical; a probe present
on one side only is a mismatch, so a harness that quietly stops answering fails
rather than passes.

**Oracle provenance.** `oracle/` is a Go module whose declared path is
`github.com/microsoft/TypeScript/tsc/oracle` and which replaces
`github.com/microsoft/TypeScript/tsc` with the `upstream/` submodule directory.
That is what lets it import the pinned `internal/...` packages without patching
or writing into the checkout. The producer verifies the submodule is registered,
initialized, clean and at the provenance pin before and after the run, reusing
the S01 check, and declares the `upstream` gitlink in its source set, so a dirty
or moved checkout cannot supply evidence.

**Fixtures.** `data/e4-fixtures.json`, generated by `scripts/gen-e4-fixtures.py`
and declared as a producer input. Bytes are hex so malformed input survives the
file. It carries the fixtures the design note names (docs/design/text.md,
section 3): byte order marks and UTF-16 decoding including unpaired surrogates
and a trailing odd byte; WTF-8 sentinels whole, split and adjacent; malformed
bytes; one, two, three and four byte sequences; both line-break sets including
U+2028 and U+2029; and the quote, control and separator characters the escape
helpers branch on. The case sweep is every code point Unicode 15.1.0 gives a
case mapping, taken from the pinned Go table. A second sweep takes the boundary
code points of the pinned Cased and Case_Ignorable range tables and places each
one after a sigma in two contexts; "cased", "case ignorable" and "neither" give
three distinct pairs of results, so a transcription error in either table shows
up instead of hiding behind a condition that is rarely reached.

**Probes.** Derived from the manifest by the same rules on both sides: every byte
offset of a text plus the declared out-of-range values, every line of the
relevant line map plus the declared out-of-range lines, and the declared
character offsets. Several of these conversions are specified to panic; a panic
is a value (`"panic"`), so panic behavior is compared rather than fatal.

**What each criterion covers in S04.**

| Criterion | Probes | Oracle entry points |
|---|---|---|
| `source_decoding` | each file fixture written to disk and read back | `osvfs.FS().ReadFile`, which is the production `decodeBytes` path |
| `helper_semantics` | case mapping, truncation, first-character lowering, surrogate encode/decode/combine, literal escaping, the full Unicode 15.1.0 case sweep and the Final_Sigma range-table sweep | `stringutil.*`, `printer.EscapeString` |
| `slice_validity` | every in-range byte slice of every text, its bytes, its recomputed validity tag and whether a `str` view exists, plus out-of-range slices | Go slicing plus an independent implementation of the tag rule |
| `utf8_positions` | both line maps, line-of-position, line-and-byte-offset, and the LSP converters with UTF-8 negotiated | `core`, `scanner`, `lsconv` |
| `utf16_positions` | the API position map in both directions, `UTF16Len`, the scanner's line/character conversion with both `allowEdits` settings, and the LSP converters with UTF-16 negotiated | `ast.ComputePositionMap`, `scanner`, `lsconv` |

**Not covered yet, by design.** `diagnostics`, `token_value_bytes`,
`token_literal_bytes`, `encoder_success_error`, `encoder_output_bytes` and
`helper_printer_semantics` have no production path before S05, S06 and S08. The
harness emits no metric for them, so those criteria stay pending and E4 as a
whole cannot pass on S04's evidence.

**Stated scope limit.** `stringutil.LowerFirstChar` reaches Go's
`unicode.ToLower`, whose tables follow the Go toolchain's Unicode version rather
than the upstream pin. `ts_jsstring` stays on Unicode 15.1.0 like the rest of the
crate (docs/design/text.md, section 2.5), so the two agree on every code point
that version defines and differ on later additions; 55 code points added after
Unicode 15.1.0 are outside the compared domain. Upstream calls this helper only
from the fourslash test harness, on ASCII command names. A comparison that also
covered Go's newer tables would pin the port to a toolchain rather than to the
provenance pin, which is the opposite of what ADR 0013's note asks for.

**Also enforced.** The run fails, rather than measuring, if
`crates/ts_jsstring/src/unicode_case_generated.rs` or `data/e4-fixtures.json` has
drifted from its generator: a stale table would make the comparison meaningless.

## e3: ownership

**Command.** `python3 scripts/e3-harness.py`.

**Shape.** There is no oracle here. Ownership is a Rust-side contract, so the
harness asserts the invariants ADR 0006's note fixes, and the review question is
whether the assertions are the right ones. Each scenario is a row of
docs/design/ownership.md, section 4, and reports the individual checks it made;
a failure names the check. Scenarios the sprint has not built are absent rather
than stubbed, so their criteria stay pending.

The scenarios run three times over the same code:

| Run | Why |
|---|---|
| release, `cargo run --release` | import validation has to hold in release builds, which is where the check-elision rule applies |
| Miri | the lazy arena's stable pages, publication and concurrent first use |
| AddressSanitizer, `-Zbuild-std` for the host target | allocation and teardown, including the standard library |

The release run's report supplies the scenario metrics; the other two supply
`miri` and `address_sanitizer` as pass or fail. Miri interprets every
instruction, so the concurrent scenario uses a smaller workload there
(`TS_E3_SCALE=reduced`); the harness still asserts that it crosses a page
boundary and still runs several threads through the miss, recheck and publish
paths.

**What each criterion covers in S04.**

| Criterion | What the scenario asserts |
|---|---|
| `id_exhaustion` | arena 0 and slot 0 are unrepresentable; ids round-trip across the full 32-bit range including the 31-bit boundary; the production counters, driven from an injected start, issue the last id, refuse the next, stay refused and saturate rather than wrap; a spent counter refuses publication in both the core and lazy arenas; owner kind is scope metadata, not a bit taken from the id |
| `wrong_owner_rejected` | equal numeric slots in two files and in two checkers of one pool generation; a file scope rejects the other file's id; checker storage is unreachable without that exact checker's operation permit; a file-only scope cannot resolve a checker-created node; a slot past the published bounds is rejected rather than aliased |
| `stale_and_recycled_ids_rejected` | an id whose owner has dropped is rejected by every scope; a replacement file takes a fresh arena id, so there is no window in which the old id resolves; a retired pool generation fails its lease at the next boundary while the storage the lease holds is still alive, and supplies no new leases |
| `concurrent_lazy_storage` | eight threads racing the same token and JSDoc keys publish exactly one node per key; every reader sees an initialized node with its supplied parent; the page directory grows and references taken before growth stay readable; a cached kind mismatch and a reparsed parent are refused, and the refusal publishes nothing and leaves the arena usable |
| `mapper_bundle_disposal` | a canonical file with three supplemental files, four independent holders, and all 24 release orders: links point both ways as ids, every member id resolves while any holder lives, sibling links resolve only through the bundle, and storage is freed exactly when the last holder drops |
| `live_owner_delta`, `live_allocation_delta` | the maximum absolute deviation from the pre-scenario baseline over every scenario, measured by counters the production owners and arenas maintain |

**Not covered yet, by design.** `shared_bound_file`, `retained_snapshot_edit`,
`independent_checker_merges`, `builder_cache_retention`,
`checker_result_retention`, `checker_ast_retention`, `api_scratch_disposal`,
`shared_pool_panic_retirement` and `release_boundaries` need programs,
snapshots, a semantic checker, a node builder or the generation gate. They are
S07 to S09 work; the harness emits no metric for them.

**One scenario is not a criterion.** `scoped_access` checks that a branded local
handle cannot be built by a caller or used with another arena. It has no
criterion of its own in `status/experiments.toml`; it exists because the
check-elision rule in ADR 0006 depends on it, and a regression there would
otherwise only show up as a later scenario passing for the wrong reason.
