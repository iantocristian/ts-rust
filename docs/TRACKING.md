# Tracking

How progress is measured in this repository. The rule that makes it strict: nobody marks work done. Status is computed from evidence by `cargo xtask status`, and a sprint closes only when its checks pass.

## The four parts

| Part | Where | What it answers |
|---|---|---|
| Ledger | `PORTS.toml` | Which upstream Go file is ported, by whom, verified by which tests, synchronized to which pin |
| Traceability | `port:` markers in Rust sources, `data/go-functions.tsv` | Which upstream functions have a Rust counterpart; per-package coverage |
| Decisions | `docs/adr/` | What was decided, why, and what supersedes what |
| Status and dashboard | `STATUS.md`, `status/status.json`, `status/history.jsonl`, `docs/status.html` | Where the port stands today and how that changed over time |

Sprints live in `sprints/` and reference the other three; experiments live in `status/experiments.toml`.

## Ledger

`PORTS.toml` has one `[[file]]` entry per non-test Go file of the pinned upstream `tsc` module, generated by `scripts/ledger-init.py` from the checkout and re-runnable after a pin bump without losing progress. Fields:

- `go`: the upstream path, for example `tsc/internal/scanner/scanner.go`.
- `package`, `crate`, `phase`: the Go package, the Rust crate it maps to, and the phase in which the crate reaches parity, from the plan's crate map.
- `kind`: `source`, `generated` (regenerated from a schema, never hand-ported), `harness` (test infrastructure), or `out-of-scope` (excluded by the target decision, for example Windows-only files).
- `status`: `planned`, `in-progress`, `ported` (Rust code exists and compiles), `verified` (its tests and the baselines it participates in pass), or `out-of-scope`.
- `rust`: the Rust file that ports it.
- `pin`: the upstream commit the entry was last synchronized to.
- `loc`: lines in the Go file, used to weight progress.

Only `status` and `rust` are edited by hand, and only in a pull request that also carries the evidence: the tests named for the crate, or the baseline run. `verified` without a passing test run is a review failure. Everything else is regenerated.

Definition of done for a crate: every `source` entry mapped to it is `verified`, every `generated` entry is produced by the generator with the drift check green, and the crate's parity gate from the plan passes.

## Traceability

Every Rust item that ports a Go function carries a marker in its doc comment:

```rust
/// port: tsc/internal/checker/checker.go:getTypeOfSymbol
fn get_type_of_symbol(&mut self, symbol: SymbolId) -> TypeId {
```

A file-level marker `//! port: tsc/internal/scanner/scanner.go` says the whole file corresponds; function markers still count individually. The denominator is `data/go-functions.tsv`, generated by `go run scripts/go-inventory/main.go <upstream>/tsc`, which lists every top-level function and method with its receiver and line range. `cargo xtask status` scans `crates/**/*.rs`, matches markers against the inventory, and reports coverage per package and the list of unported functions. Unknown markers, ones that name no upstream function, fail the status run, which is how stale markers are caught after a pin bump.

Coverage is reported for `source` files only. It is the number that answers "how far is the checker" without anyone's opinion.

## Decisions

Architecture Decision Records in `docs/adr/`, numbered, one decision each, with `Status` (`Proposed`, `Accepted`, `Amended`, `Superseded`), `Context`, `Decision`, `Consequences`, and `Evidence` linking the upstream code that motivated it. A pull request that changes behavior covered by an ADR either amends it (adding an `Amendments` entry) or supersedes it with a new ADR. The pending technical items of the plan become ADRs when the owner decides them; until then they are listed in `docs/adr/README.md` as proposed.

## Sprints

One file per sprint, `sprints/S01.toml` and so on:

```toml
id = "S01"
title = "Contracts, workspace, oracle"
goal = "One sentence."
exit = [                                  # machine checks; the sprint is done when all pass
  "exp.E1.pass == 1",
  "file[tsc/internal/scanner/scanner.go].status == verified",
]

[[item]]
id = "S01-1"
title = "..."
kind = "task"                             # task | ledger | experiment | adr
ref = "tsc/internal/scanner/scanner.go"   # ledger path, experiment id, or ADR number
done_when = ["file[tsc/internal/scanner/scanner.go].status >= ported"]
```

A check is `<metric> <op> <value>`. Metrics come from the status run (see below); `status` values order as `planned < in-progress < ported < verified`. Items without `done_when` are checklist items and are reported, not enforced.

## Experiments

`status/experiments.toml` holds E1 to E8 with their thresholds from the plan. A measurement is recorded by filling `measured` and `measured_at`; `pass` is computed. Extrapolations are recorded in `note`, never in `measured`.

## Status runs

```
cargo xtask status            # regenerate STATUS.md, status/status.json, docs/status.html
cargo xtask status --record   # additionally append today's numbers to status/history.jsonl
cargo xtask check S01         # exit code 1 if the sprint's checks do not all pass
```

CI runs `status` on every push and `status --record` nightly, and commits the results. The metrics available to checks:

| Metric | Meaning |
|---|---|
| `ledger.files_total`, `ledger.files_ported`, `ledger.files_verified` | Counts over in-scope `source` and `generated` entries |
| `ledger.loc_verified_ratio` | Verified lines over in-scope lines |
| `ledger.phase[N].loc_verified_ratio`, `ledger.crate[name].loc_verified_ratio` | The same per phase and per crate |
| `file[path].status` | One entry's status |
| `functions.total`, `functions.ported`, `functions.ratio` | Function-level coverage over `source` files |
| `functions.package[pkg].ratio` | The same per Go package |
| `exp.E1.measured`, `exp.E1.threshold`, `exp.E1.pass` | Experiments; `pass` is 1 or 0 |
| `sprint.S01.done` | 1 when every exit check of the sprint passes |

## Pin bumps

Moving the upstream pin is a sprint item of its own: bump the submodule, rebuild the oracle, regenerate from the schemas, run `scripts/ledger-init.py --pin <new>` and `go-inventory`, and port every entry whose Go file changed between its recorded pin and the new one. The status run lists those entries as `stale` until their pin field is updated in the same pull request as the ported diff.
