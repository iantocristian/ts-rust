# S04: text and ownership leaves

S04 implements `ts_jsstring` and `ts_arena` against upstream pin
`1f70213d4922b434345f639b441681e470c7cfc1`. The text crate maps 47 unique upstream
functions. Arena ownership is a new Rust implementation of the accepted contract.
Function mappings establish traceability; the registered `e3` and `e4` producers
provide the behavioral measurements used by [S04](../sprints/S04.toml).

## Implemented scope

| Crate | Implemented leaf contract |
|---|---|
| [`ts_jsstring`](../crates/ts_jsstring/SLICE.md) | Shared immutable bytes; UTF-8, WTF-8 and raw classification; checked byte slices; source BOM decoding; sentinel-aware and standard decoding; casing, truncation, surrogate and escape helpers; distinct API/LSP/scanner position rules and ECMAScript/LSP line maps |
| [`ts_arena`](../crates/ts_arena/README.md) | Checked node/symbol IDs, never-reused arena identities, file/bundle/scratch owners, retained references, immutable core storage, lazy page publication, owner/generation validation and checker identity/lease primitives |

The public position functions accept byte slices and preserve each upstream
operation's rounding, clamping and panic behavior. UTF-16 offset 1 inside `😀`
maps to byte offsets 1, 0 and 4 in the API, LSP and scanner paths respectively.
Source slices are tested after BOM decoding, including slices that split a valid
UTF-8 sequence or surrogate sentinel.

## E4 measurements

The captured differential run on 6 September 2026 compared **75,997 probes in 400
scenarios**, with **zero mismatches**, against the actual pinned Go functions.
The [execution artifact](../status/evidence/a9b1ab540fa02447f7be3147954699c88f814bb61a5f13b29b817214dcee8377.json)
contains the probe counts, complete scenario outcomes, command logs and provenance.
The generated status reports validate it against the current source and inputs.

| Implemented criterion | Probes | Observed result |
|---|---:|---|
| Source decoding | 66 | Pass |
| Helper semantics | 24,325 | Pass |
| Slice validity | 13,064 | Pass |
| UTF-8 positions | 16,598 | Pass |
| UTF-16 positions | 21,944 | Pass |

Both canonical result streams have SHA-256
`08967bccf2640196173674d63a12732ecaee96d8382224e620e5b9bdd1abbad4`.
The producer exports a clean copy of the pin and adds access wrappers for private
Go helpers. It compares complete ordered results, actual bytes and string views,
and panic occurrence. JSON types remain distinct; missing, extra, reordered or
malformed results fail the run. Every probe must match for its scenario to pass.

Fixtures include malformed bytes, BOMs and odd UTF-16 payloads, surrogate
sentinels, byte fragments, signed and wrapped wire offsets, all escape flags,
the generated casing mappings, and Final_Sigma contexts at property-range
boundaries and stride gaps. The casing generator's `--check` runs before the
differential comparison. The corpus, toolchain pins and frozen scenario IDs live
under [`data/s04/`](../data/s04/).

## E3 measurements and limits

Seven scenarios pass in debug, release, Miri and AddressSanitizer: ID exhaustion, wrong-owner
rejection, stale/recycled-ID rejection, concurrent lazy storage, mapper-bundle
disposal, owners returning to baseline and allocations returning to baseline.
The producer requires actual completion of the same seven scenario functions in
each mode before emitting the instrumentation metrics. The concurrent scenario
races four workers, each checking all 300 newly allocated nodes, with a retained
reference reader synchronized across page growth. Its reads are bounded so a
worker deadlock cannot be masked by a permanently runnable observer. Native test
success alone cannot satisfy the instrumentation gates. The
[execution artifact](../status/evidence/6b1a32561448e01fd30a425378965612be9bd55f507102dcc6a2192bae0c0b6a.json)
records all four runs and measured zero final-drop owner/allocation deltas.

Counters measure live owners and explicitly tracked storage units: owner objects,
nonempty core/symbol slabs and lazy pages. They exclude payload allocations,
cache/directory bookkeeping and other global allocator calls. They are neither
heap-byte measurements nor RSS. Scenarios require nonzero observed peaks, then
measure final-drop deltas against their initial snapshots; payload-drop assertions
also check storage destruction.

These leaf measurements leave the full E3 and E4 experiments open. Later sprints
must exercise semantic checker merges, real programs/snapshots and registries,
builder/transform dependencies and atomic retirement versus result commitment.
Scanner tokens and diagnostics, parser/encoder behavior, literal types and whole
printer integration also remain pending. Memory and CPU targets need the later
compiler workloads; storage-unit counters do not measure those targets.

## Reproduce and capture

Use the pinned stable Rust toolchain and Go 1.27.1 on `PATH`. Install the separate
instrumentation toolchain recorded in `data/s04/toolchains.toml`:

```sh
RUSTUP_HOME="$PWD/target/s04-rustup" rustup toolchain install nightly-2026-09-05 \
  --profile minimal --component miri --component rust-src --no-self-update
cargo test --package ts_jsstring --locked
cargo test --package ts_arena --lib --locked
cargo test --package ts_arena --lib --release --locked
cargo xtask run e4
cargo xtask run e3
cargo xtask status
cargo xtask check S04
```

The producer keeps instrumentation caches under `target/`, runs the arena tests
with one test thread, and rebuilds the standard library for AddressSanitizer.
Miri uses its default exposed-provenance model with empty `MIRIFLAGS`, retaining
the warning from `parking_lot_core` 0.9.12's integer-to-pointer queue reconstruction.
Strict provenance rejects that dependency operation. The production lock remains
in use. As the pinned nightly's `share/doc/miri/README.md` documents, these
operations limit detection of bugs involving the affected memory/pointers;
the other aliasing, race and leak checks remain enabled.
On macOS, ASan's leak detector is disabled because that platform does not support
it; final-drop counters and Miri remain separate checks. No instrumented metric
is supplied by the native example itself.

The status workflow reruns both producers and requires S04 on macOS and Linux,
alongside the bootstrap and quality gates. A successful capture can contain
failing measured criteria; `cargo xtask check S04` evaluates the required metrics,
including current instrumentation evidence. Full experiment gates remain defined
in [`status/experiments.toml`](../status/experiments.toml).
