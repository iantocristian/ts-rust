## Scaffold boundary corrections

Unbranded type/signature IDs and type storage are now crate-private. Public
operations no longer dereference to mutable checker state, so external callers
cannot move same-numbered local IDs between stores or swap the state of two
owners. Retained public handles and their owner validation remain later P1 work.

Same-thread reentry detection now lives in `CheckerIdentity::lease`, covering
direct lease acquisition as well as `CheckerOwner::operation`. It rejects
reentry before waiting; other-thread contention still waits. The lease still
retires its generation during unwinding. Tests cover direct lease to operation,
operation to direct lease, ordinary contention, panic retirement and API access
rejection through compile-fail examples.

## Initial storage result

This is the first production storage candidate, using provisional vectors and
the existing hash map. There is no alternative layout trial or timing result.
The small trace is constructed to exercise interning and growth boundaries;
it does not model the subset's distribution of type families.

Final capture: `storage-source-closure`, darwin/arm64, Go 1.27.1, Rust 1.97.1 release,
locked dependencies, mimalloc with requested-allocation counters. Exact input,
overlay, observations, compiler artifact, executable and source hashes are
retained in the archive under `tools/s08/results/`.

| Observed quantity | Go | Rust |
| --- | ---: | ---: |
| Types created | 524 | 524 |
| String intern entries | 261 | 261 |
| Requested bytes during construction | 92,424 | 194,408 |
| Retained endpoint delta | 70,608 | 100,084 |

Input strings and empty checker setup precede the interval. The interval includes
result-root backing, type records, payload rows, interning capacity and growth.
Go's retained endpoint is process-wide post-GC `HeapAlloc`; Rust's is live
requested allocator bytes. These units and the small Go process-wide sample
do not establish a per-type ratio or an E5 result. Type-owned input backing must
be charged in the full census even when it is prepared outside this diagnostic.

Rust's common record is 32 bytes and its string row 40 bytes. The common-record
vector retains 32,768 bytes for 524 live entries; string rows retain 40,960 bytes
for 522 live entries. Including the intrinsic rows, these vectors alone have
36,144 bytes of unused capacity. Rust requests 94,324 more bytes than it retains
during this interval. This exposes a capacity/growth cost to address in the
full P1 storage measurement; it does not justify choosing a replacement before
object, union, tuple, list and cache membership are measured.

The first capture (`storage-initial`) matched constructor observations but had a
**negative Go retained delta of −24,912 bytes**. Decoded requests could die after
the constructor loop, allowing their backing to be collected between endpoints.
Explicit `KeepAlive` calls now retain requests, decoder buffers, raw input and
text through both checkpoints. The corrected captures report 65,288–70,608 Go retained bytes; that variation
is another reason not to turn this process-wide diagnostic into a footprint gate. The original raw result remains archived
as an unusable retained-memory observation; it is not silently replaced.
