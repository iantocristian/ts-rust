# S08 P3 — Types, signatures, relations and ordering

Status: in progress on `codex/s08-p3`, from merged P2 (`66cc5f4`).
This record implements P3 of the [S08 plan](S08-implementation-plan.md).
It does not change the 9,369-variant acceptance denominator or certify P3 from a
small fixture suite. Full acceptance pass count remains unmeasured at this point.

## Increment sequence

1. **Source unions and member queries (P3a).** Connect source union nodes to the
   existing constructor, preserve aliases/reduction/order, resolve public data
   properties across constituents, and check the supported primitive union
   assignments. Extend the production query/display path and compare real programs.
2. **Intersections, arrays and tuples.** Add source intersection reduction and
   properties, reference member instantiation, required/optional/rest/readonly
   tuple semantics, and their printer paths. Generic array declarations must be
   executed through their real instantiation machinery, not synthesized as empty
   stand-ins to get an array fixture through.
3. **Signatures and generic declarations.** Grow signatures, constraints,
   defaults, mappers, inference and overload relations together. Load named real
   library capabilities as their dependency paths become executable.
4. **Recursive relations and ordering closure.** Extend relation modes and
   recursive assumptions, source comparators and residual identities; run the
   frozen relater/comparator discriminators. Keep full body/flow/emit closure in
   P4 and later display closure in P5.

Each increment ends with named completed cases, remaining unsupported operations,
an updated PR and regenerated committed status views. There is no performance or
capture/replay project in this sequence; use the existing small native observer.

## P3a implementation plan

### Contracts and ownership

- Authority is the pinned `checker.go`: `getTypeFromUnionTypeNode`,
  `getPropertiesOfType`, `getPropertiesOfUnionOrIntersectionType`,
  `createUnionOrIntersectionProperty`, and the reached assignment-relation rules.
- Resolve source constituents in source order before constructor sorting. Retain
  alias identity and denormalized origins through `getUnionTypeEx`; reversing
  source order is not permission to reorder constructor calls.
- Source symbols and declarations remain immutable. Synthesized common properties
  and copied declaration lists belong to the checker. Cached IDs do not retain
  another owner independently; the existing program retention supplies their
  source roots. Validate public handles before entering private lookup paths.
- Cache a resolved property list only after its entire operation succeeds. Cache
  synthesized properties by name for repeat identity. Preserve upstream deferred
  normalization for more than two property types so property discovery does not
  eagerly change type-creation order.
- Ordinary cache hits borrow the stored list or copy IDs as required by the public
  API. First resolution walks constituents and allocates checker-owned symbol/list
  storage. No new per-node locks or owner clones are needed.

### Steps

1. Add named native programs for primitive/literal reductions, named nested
   unions, reversed source order, common/missing object properties, optional
   properties, three-constituent deferred property types and recursive property
   references. Include valid and invalid primitive union assignments.
2. Reuse the existing observer with a selected request file; do not fork its
   diagnostics, graph normalization or archive validator. Both display modes
   continue to use no enclosing declaration, with the corrected P2 flags.
3. Connect source union syntax and declaration traversal. Unsupported generic,
   index-signature, accessor, intersection and relation branches stay explicit.
4. Put member resolution and union property synthesis in a separate checker module.
   Reuse the apparent primitive wrappers and structured member stores. Preserve
   flags, declaration order, optionality, partial-property filtering, property
   identity, deferred types and recursive cache behavior within the supported
   public data-property slice. Unsupported branches cannot silently omit members.
5. Connect primitive union assignment relations in their source order. Structural
   union matching, excess-property elaboration and recursive relations must not
   be approximated by unconditional success or by swallowing an unsupported error.
6. Run the named Go/Rust comparison and targeted runtime regressions for failed
   resolution retries, repeated identity, cross-checker handles and recursion.
   Reuse P2 tests; extend the existing printer where these types require it.
7. Inspect final changes and ordinary-path allocation/ownership costs, run focused
   checks, retain the small native/Rust archive, stage the final inventory,
   regenerate all four status views and run `status --check-committed` before push.

### Plan review

P1 union constructors alone do not establish source support. The critical new
counterexamples are a missing union property being exposed, three property types
being normalized eagerly, alias identity lost during flattening, and a partial
resolution cache returning success on retry. Native graph and display comparison
must cover the whole property symbol, not just its printed type.

Arrays/tuples depend on generic reference members; including them in this first
increment would disguise the signature/instantiation dependency. Intersections
also require a distinct reduction and property contract. They remain the next
increment, not a union implementation reused with a different token.

P2's expression cache still supports normal checking only. When flow arrives,
cache fills must save, clear and restore the flow stack/cache as pinned Go does.
Context-sensitive type display and inferred object widening also remain explicit
pending work. Go's synchronous interface checks and transient merge-parent guard
remain unchanged.

## Results

P3a is implemented and ready for review. P3 as a whole remains in progress.

The pinned Go comparison passes **27 queries across ten programs**, plus all
four shared-file merge modes. It compares symbol graphs (including flags,
declarations and parents), type/object flags, both context-free display modes,
properties, diagnostic phases and exact error-baseline bytes. There are no
unsupported operations or mismatches in this named capture.

| Named program family | Queries |
| --- | ---: |
| Union reduction, boolean folding and reversed constituents | 7 |
| Named nested unions and origins | 4 |
| Common and missing object members, reversed union syntax | 4 |
| Optional property read types | 3 |
| Three-way deferred property normalization | 4 |
| Recursive property reference | 1 |
| Valid and invalid primitive union assignments | 1 |
| Primitive wrapper members, Object fallback, entirely missing property | 3 |

The original P2 suite also passes unchanged: 29 queries across six programs,
using its existing native observations. The new capture reuses the same observer
and validator through `--spec`; it does not copy the oracle or protocol.
The wrapper/Object cases define actual source interfaces and compare their native
behavior; they are not substitutes for the pending standard-library closure.

Two native counterexamples extended the implementation: diagnostic display of a
parentless global alias under `UseFullyQualifiedType`, and preserving the
original offending literal when a target union contains singleton types. Other
qualification paths still fail explicitly.

Validation: 41 checker unit tests, 16 compiler semantic tests and nine protocol
tests pass; package Clippy across all targets/features passes with warnings
denied. The new regressions prove deferred normalization, repeated symbol/type
identity with unchanged allocation counts, failure after a successfully cached
property, recursive type identity on a 512 KiB stack, and literal diagnostic
arguments. This small recursive fixture does not certify deep-stack growth or
recursive relation semantics. P0's original captures were validated and reused;
only the broader inventory fingerprint of the shared checkpoint script changed.

Implementation review retained the following boundaries: no index signatures,
accessor/method synthesis, instantiated/mapped property equivalence, exact
optional write types, object-literal write-partial properties or structural union
relation elaboration. Unsupported failures remain observable. Source readonly
modifier checking remains later grammar work, although property lookup preserves
readonly information when present. Intersections, array/tuple instantiation,
generic libraries, signature/inference work and full relation/order fixtures
remain the subsequent P3 increments.

A union lists candidate names from its first constituent when it has no index
signatures. Constituent lookup uses borrowed member tables and only resolves
names actually requested; it does not eagerly materialize every constituent's
members. Completed synthesized properties may remain cached after a later
property fails, but the full property list is published only after success.
Per-checker deferred constituent lists add retained storage that P7 must charge;
no memory or throughput result is claimed here.

The small archive and provenance are under `data/s08/p3a/`; replay commands are
in `tools/s08/p3/README.md`. Committed status views are refreshed at delivery.
The 9,369-variant full acceptance pass count remains unmeasured; no gate or
threshold has been changed.
