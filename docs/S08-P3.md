# S08 P3 — Types, signatures, relations and ordering

Status: in progress. P3a merged in PR #17 (`8540b68`); the next increment
is on `codex/s08-p3b`.
This record implements P3 of the [S08 plan](S08-implementation-plan.md).
It does not change the 9,369-variant acceptance denominator or certify P3 from a
small fixture suite. Full acceptance pass count remains unmeasured at this point.

## Increment sequence

1. **Source unions and member queries (P3a).** Connect source union nodes to the
   existing constructor, preserve aliases/reduction/order, resolve public data
   properties across constituents, and check the supported primitive union
   assignments. Extend the production query/display path and compare real programs.
2. **Intersections, arrays and tuples.** Add source intersection reduction and
   properties, reference member instantiation, required/optional/rest/readonly
   tuple semantics, and their printer paths. Generic array declarations must be
   executed through their real instantiation machinery, not synthesized as empty
   stand-ins to get an array fixture through.
3. **Signatures and generic declarations.** Grow signatures, constraints,
   defaults, mappers, inference and overload relations together. Load named real
   library capabilities as their dependency paths become executable.
4. **Recursive relations and ordering closure.** Extend relation modes and
   recursive assumptions, source comparators and residual identities; run the
   frozen relater/comparator discriminators. Keep full body/flow/emit closure in
   P4 and later display closure in P5.

Each increment ends with named completed cases, remaining unsupported operations,
an updated PR and regenerated committed status views. There is no performance or
capture/replay project in this sequence; use the existing small native observer.

## P3a implementation plan

### Contracts and ownership

- Authority is the pinned `checker.go`: `getTypeFromUnionTypeNode`,
  `getPropertiesOfType`, `getPropertiesOfUnionOrIntersectionType`,
  `createUnionOrIntersectionProperty`, and the reached assignment-relation rules.
- Resolve source constituents in source order before constructor sorting. Retain
  alias identity and denormalized origins through `getUnionTypeEx`; reversing
  source order is not permission to reorder constructor calls.
- Source symbols and declarations remain immutable. Synthesized common properties
  and copied declaration lists belong to the checker. Cached IDs do not retain
  another owner independently; the existing program retention supplies their
  source roots. Validate public handles before entering private lookup paths.
- Cache a resolved property list only after its entire operation succeeds. Cache
  synthesized properties by name for repeat identity. Preserve upstream deferred
  normalization for more than two property types so property discovery does not
  eagerly change type-creation order.
- Ordinary cache hits borrow the stored list or copy IDs as required by the public
  API. First resolution walks constituents and allocates checker-owned symbol/list
  storage. No new per-node locks or owner clones are needed.

### Steps

1. Add named native programs for primitive/literal reductions, named nested
   unions, reversed source order, common/missing object properties, optional
   properties, three-constituent deferred property types and recursive property
   references. Include valid and invalid primitive union assignments.
2. Reuse the existing observer with a selected request file; do not fork its
   diagnostics, graph normalization or archive validator. Both display modes
   continue to use no enclosing declaration, with the corrected P2 flags.
3. Connect source union syntax and declaration traversal. Unsupported generic,
   index-signature, accessor, intersection and relation branches stay explicit.
4. Put member resolution and union property synthesis in a separate checker module.
   Reuse the apparent primitive wrappers and structured member stores. Preserve
   flags, declaration order, optionality, partial-property filtering, property
   identity, deferred types and recursive cache behavior within the supported
   public data-property slice. Unsupported branches cannot silently omit members.
5. Connect primitive union assignment relations in their source order. Structural
   union matching, excess-property elaboration and recursive relations must not
   be approximated by unconditional success or by swallowing an unsupported error.
6. Run the named Go/Rust comparison and targeted runtime regressions for failed
   resolution retries, repeated identity, cross-checker handles and recursion.
   Reuse P2 tests; extend the existing printer where these types require it.
7. Inspect final changes and ordinary-path allocation/ownership costs, run focused
   checks, retain the small native/Rust archive, stage the final inventory,
   regenerate all four status views and run `status --check-committed` before push.

### Plan review

P1 union constructors alone do not establish source support. The critical new
counterexamples are a missing union property being exposed, three property types
being normalized eagerly, alias identity lost during flattening, and a partial
resolution cache returning success on retry. Native graph and display comparison
must cover the whole property symbol, not just its printed type.

Arrays/tuples depend on generic reference members; including them in this first
increment would disguise the signature/instantiation dependency. Intersections
also require a distinct reduction and property contract. They remain the next
increment, not a union implementation reused with a different token.

P2's expression cache still supports normal checking only. When flow arrives,
cache fills must save, clear and restore the flow stack/cache as pinned Go does.
Context-sensitive type display and inferred object widening also remain explicit
pending work. Go's synchronous interface checks and transient merge-parent guard
remain unchanged.

## P3a review amendments

- **Constituent checks — confirmed and fixed.** `UnionType` now checks each
  source child in order before requesting the constructed type, as pinned
  `checkUnionOrIntersectionType` does. Construction alone can skip diagnostics
  hidden in deferred object members, even if the resulting union is reduced
  to `unknown`. A type-cache hit is not a completed source check.
- **Negative native observations.** `union-duplicate-properties` records two
  TS2300 diagnostics and TS2717 with related TS6203. Rust now rejects the
  unported duplicate/subsequent-property diagnostic path. `union-missing-type`
  records TS2304; Rust rejects the unported source-name suggestion path.
  Semantic, combined and baseline operations stay explicitly unsupported;
  neither program can claim an empty successful error baseline.
- **Synthetic property parent — corrected.** Read the bound declaration's raw
  symbol parent, matching `firstValueDeclaration.Symbol().Parent`, rather than
  routing through `getSymbolOfDeclaration` and checker-local merge resolution.
  No observable difference is claimed in the current fixtures.
- **Comparison scope — corrected.** The report takes scope from the frozen
  request. Replays no longer inherit a live checkpoint label. Historical P2
  observations remain unchanged and still match 29/29; the current comparison
  output intentionally uses that archive's request scope.
- **Literal-union error generalization — valid, deferred.** Current expression
  checking cannot yield a union type: identifiers and other union-producing
  expressions are unsupported. Before enabling them in P4 (or an earlier P3
  increment), reuse `isLiteralType` and port `getBaseTypeOfLiteralType`, including
  its cached union mapping. Add a source literal-union assignment discriminator;
  do not generalize a union by selecting a single constituent's primitive type.
- Index-signature member enumeration and instantiable singleton checks remain
  explicit unsupported operations. This review does not broaden those paths.


## P3b implementation plan — source intersections

This is the first review unit of the compound-type step. Array/tuple source
support follows it with actual generic member instantiation: the existing P1
reference and tuple records alone cannot implement those queries. Keep those
operations explicitly pending rather than inventing empty array interfaces.

1. Port ordered intersection construction in `intersection.rs`. Flatten nested
   intersections, regularize literals, preserve first-occurrence order, reduce
   disjoint primitives, remove redundant supertypes, preserve the source-only
   `string & {}` exception, and intern by ordered IDs and alias. Port primitive
   union intersection, nullable factoring, divide-and-conquer and cross-product
   construction together, including denormalized origins. Reuse the existing
   cross-product size guard; its unported diagnostic must remain Unsupported.
2. Connect intersection syntax to source checking and construction. Check every
   child in source order even after a prior query cached the resulting type.
   Resolve all constituent types before sorting or reducing any compound result.
3. Share the existing union-property algorithm through explicit union/intersection
   branches. Intersection names come from all constituents in source order;
   optionality and readonly combine with AND, versus OR for unions. Use separate
   augmented/non-augmented caches and preserve Go's cache propagation rule.
   Deferred properties select union or intersection from their containing type.
4. Add lazy never-intersection reduction and union reduction over intersections.
   A conflicting literal discriminant can reduce the whole object to never;
   plain `string` versus `number`, optional conflicts, and pre-existing never
   properties cannot be treated as the same case. Mark an active reduction to
   break recursive reads, but clear its computed flag on any Unsupported/error
   so a failed query cannot turn into a successful retry.
5. Extend type display through generated intersection AST nodes and the existing
   printer. Reduce before alias display unless NoTypeReduction is requested;
   preserve intersection origins and parenthesization within unions.
6. Capture named programs with the existing observer and protocol, including all
   P3a requests and their two named pending failures. Add reductions, order,
   common/disjoint/optional properties, conflicting discriminants, distribution,
   Object augmentation and recursive references. Compare exact flags, symbols,
   both display modes and diagnostics; retain any unsupported/mismatched rows.
7. Add focused Rust regressions for lazy flags, retry after partial discovery,
   deferred intersection normalization and stable property/type identities.
   Review the final implementation against Go, run affected tests/lints and
   refresh all committed views. Archive the small capture and open a review PR.

### Plan review and boundaries

The largest traps are treating intersections as sorted unions, reducing a plain
never-valued property as a discriminant, inheriting Object properties while
enumerating intersections, and setting IsNeverIntersectionComputed permanently
before a failing resolution. These require independent source cases and retry
checks, not only constructor unit tests.

All caches, symbols, declaration lists and type rows remain checker-owned;
source trees and bound symbols remain immutable. Constructor scratch holds
ordered IDs and a dedup set; stored lists are shared under the existing TypeList
contract. Cached property reads borrow the table; public property lists retain
the existing copy-of-IDs API. No per-node locks, new owners or dependencies.

This increment does not claim signature/index/accessor/mapped-property support,
constraint reduction, generic this-type instantiation, exact optional write
semantics or structural assignment relations. Reached unported paths fail
explicitly. Arrays, tuples, generic libraries and full relater/comparator closure
remain P3 work. P3a's literal-union diagnostic follow-up remains a prerequisite
for union-producing expression support.


## P3b results and implementation review

Source intersection construction, data-property queries, lazy discriminant
reduction and display are implemented. The checkpoint has 69 queries in 23
programs, including all P3a requests. **19 complete programs (64 queries)** and
all four shared-file merge modes match Go. The original P2 run also remains
29/29 with byte-identical Rust observations against its existing native capture.

Four programs remain explicitly incomplete, so the complete checkpoint reports
`matched: false`: the two P3a negative programs, the new intersection with
invalid constituent declarations, and readonly-property grammar checking. The
readonly query graphs themselves match (including AND-combined readonly flags);
that is not a completed semantic-diagnostics result. No request is filtered out.

The new cases cover ordered and duplicated constituents; unknown/any/never and
disjoint primitive reductions; `string & {}`; optional and conflicting properties;
primitive-union intersections; nullable factoring; Cartesian distribution and
three-input splitting; denormalized origins; Object augmentation; and recursive
properties. Signature/index/accessor/generic constraints and structural relations
remain unsupported. Array/tuple source instantiation and generic-library closure
are the next compound-type work, not part of this completed increment.

Focused validation passes: 41 checker unit tests, 21 compiler semantic tests,
ten protocol tests and package Clippy across all targets/features with warnings
denied. The unchanged printer's intersection emit/precedence path is exercised
by the native comparisons. Tests verify NoTypeReduction, lazy flag publication,
flag cleanup after failure, repeated identity/counts, and deferred property type
normalization. The 512 KiB recursion case checks recursive references and stable
properties; it is not a deep-stack or recursive-relater certification.

The review confirmed several details that must survive later generic work:

- `I & I` flattens into the constituents of `I`; two recursive `next: I`
  declarations therefore synthesize an unaliased `A & B` property type, rather
  than reusing the named `I` type. The native display confirms this difference;
  repeated requests must reuse the new property's type identity.
- The non-augmented property cache propagates complete entries to the augmented
  cache, without overwriting an existing entry. Intersection enumeration never
  imports Object fallback properties into its candidate list.
- `filterType` preserves a denormalized origin only when the same number of
  constituents can be removed there. Nullable factoring uses this path rather
  than rebuilding an unrelated union.
- A failed lazy reduction clears IsNeverIntersectionComputed. Successfully
  completed property entries may remain cached, but they cannot turn the failed
  property-list/reduction operation into success on retry.
- Constructor scratch uses ordered IDs and a dedup set. Stored constituent lists
  share the existing TypeList ownership. Existing census accounting includes the
  intersection cache and both property tables; no performance result is claimed.

Evidence and replay instructions are in `data/s08/p3b/` and `tools/s08/p3b/`.
Tracker validation and committed views are refreshed at delivery. P3 and S08
remain in progress, with no acceptance denominator or threshold changes.

### P3b review amendments

The four follow-up notes were checked against the pin. Three corrections and
one explicit implementation precondition are retained:

- Property synthesis now sets `HasLiteralType` for pattern literal types as well
  as ordinary literals. A constructed-type regression verifies that
  ``{ a: `x${string}` } & { a: number }`` reduces to `never`, while the corresponding
  `string`/`number` property conflict does not reduce the entire object. This
  exercises the existing template constructor; source template type nodes remain
  unsupported.
- `getApparentType` maps `object` to the existing empty object type. The native
  request adds standalone `object`, intersections in both orders, and a union
  exercising Object-member augmentation. All four queries and their program
  diagnostics match Go.
- The member-reader comment records why resolving wrappers per constituent
  currently suffices for the observed properties. Before enabling interface
  `this`, type parameters or heritage, port apparent intersections and
  `getTypeWithThisArgument`; this shortcut is not that implementation and does
  not claim the same intermediate type-creation counts.
- Display substitutes a union's origin before dispatching on its type family,
  as Go does. A future index (`keyof`) origin now reaches the explicit unsupported
  type-family result instead of an inappropriate compound-payload read. No index
  constructor or source `keyof` support is added; this latent branch was verified
  by source inspection rather than a fabricated index payload.
